# Backend（后端）

## 定义

**Backend（后端）**：用户看不到，但在背后处理数据、逻辑、安全的部分。

大白话：**后端是软件的「大脑」和「内脏」。** 用户看不到它，但它的工作决定了软件能不能保存你的数据、能不能处理你的请求。

## 例子

一个 Todo 应用：

- 前端：你看到输入框和列表
- 后端：接收你添加的任务 → 保存到数据库 → 下次打开时把任务返回给你

## 为什么需要后端

纯前端（只有 HTML / CSS / JavaScript）的缺点是：**关掉浏览器，数据就没了。**

需要这些功能时，就需要后端：

- 用户登录 / 注册
- 数据长期保存（Todo、笔记、订单）
- 调用需要保密的功能（例如 AI API，不能在浏览器里暴露密钥）
- 多个用户的数据互相隔离

## 常见的后端概念（大白话版）

| 术语 | 大白话 |
| --- | --- |
| Server（服务器） | 一台 24 小时开机的电脑，负责接收请求和返回数据 |
| API（接口） | 前后端之间「递话」的窗口，例如 `/api/todos` |
| Database（数据库） | 保存数据的地方 |
| 请求 / 响应 | 前端「问」后端拿数据（请求），后端「答」（响应） |

## 新手误区

❌ 一开始就上后端。

✅ 先做纯前端 MVP，跑通了，再按需加后端。

「按需」的意思是：只有当你真的需要保存数据或登录时，才引入后端。这是 [Principle 4：Small Steps](../../README.md) 的体现。
