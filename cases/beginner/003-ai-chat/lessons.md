# Case 003 · Lessons（经验教训）

## 学到了什么

- **API（接口）**：前端和后端通过接口通信，像「递纸条的窗口」
- **为什么 Key 不能放前端**：前端代码用户能看到，放前端等于把钥匙交给所有人
- **环境变量**：`.env` 是「只有服务器知道的秘密纸条」
- **加载状态**：网络请求需要时间，界面要告诉用户「正在处理」
- **错误处理**：调用外部服务一定会失败，所以要设计「失败时怎么办」

## 哪里容易出错

### 1. Key 误提交

⚠️ 最严重的问题。检查 `.gitignore` 包含 `.env`，提交前用 `git status` 确认。

### 2. CORS 错误

前端直接请求 AI API 会触发 [跨域问题](../../debugging/common-errors/cors-error.md)。所以让后端转发。

### 3. 请求一直转圈

常见原因：后端没启动、接口路径不对、响应格式不符合预期。看 Network 和终端日志。

### 4. 模型名写错

报 `400` 时先检查模型名和参数格式，以服务商文档为准。

## AI 为什么容易犯错

- **SDK 版本旧**：AI 可能写出旧版调用方式，报错时对照官方文档
- **把 Key 写进代码**：你提醒得不够，AI 就把 Key 硬编码了。所以 Prompt 里要明确要求
- **前后端协议不一致**：前端发 `{message}`，后端读 `{text}`，就会 400。出现时让 AI 检查字段名

## 一句话总结

> 调用 AI 的本质是「把消息送出去，把回答接回来」。先让这个闭环跑通，再谈高级功能。
