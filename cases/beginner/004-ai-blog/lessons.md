# Case 004 · Lessons（经验教训）

## 学到了什么

- **CRUD（增删改查）**：几乎所有应用的核心操作，就这四件事
- **数据库表（Table）**：像 Excel 表格，一行是一条记录
- **接口设计**：先想好「接口长什么样」，再写代码，思路会清晰很多
- **项目分层**：把「路由、数据库操作、页面」分开，修改时不用翻整个项目

## 哪里容易出错

### 1. 数据库文件被 .gitignore 忽略或丢失

SQLite 数据库是一个文件（如 `blog.db`）。本地开发数据别提交，但要在 README 写清楚如何初始化。

### 2. 接口参数不匹配

前端发的字段和后端读的字段不一致（例如 `content` vs `body`）。让 AI 统一检查字段名。

### 3. 重启后数据消失

检查数据库文件是否真的创建了、连接的是不是同一个文件。

## AI 为什么容易犯错

- **建表逻辑不一致**：AI 可能在不同接口里对表结构假设不同，报错时让它打印表结构核对
- **忽略「先设计再实现」**：所以我们的 Prompt 明确要求先给设计

## 一句话总结

> 数据能「活过重启」，项目才真正开始。数据库是这一步的里程碑。
