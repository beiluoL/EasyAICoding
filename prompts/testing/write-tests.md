# write-tests（编写测试）

## 适用场景

- 你想给项目写自动化测试（Test）
- 你想确保修改没弄坏已有功能
- 你想学习测试是什么、怎么写

## 你需要提供什么

- 项目：`{{PROJECT}}`
- 要测试的功能：`{{FEATURE}}`
- 关键文件：`{{FILES}}`

## 完整 Prompt

```text
我的项目：{{PROJECT}}

请为这个功能写测试：{{FEATURE}}
相关文件：{{FILES}}

要求：
1. 先告诉我你计划测试哪些场景（正常情况、边界情况、错误情况）
2. 选择最简单、最常用的测试工具，不要引入复杂框架
3. 写完告诉我：如何安装、如何运行测试、预期输出是什么
4. 用大白话解释每个测试在验证什么
5. 如果我的项目结构不适合写测试，先告诉我，不要硬写
```

## 预期行为

- 先列测试场景再写代码
- 使用简单常见的测试工具
- 有明确的运行方式和预期输出

## 常见问题

### 测试跑不过？

把完整错误信息发给 AI，用 [debug-error](../debugging/debug-error.md) 流程。

### 测试有用吗？

有用。它能在你修改代码后自动告诉你「有没有弄坏东西」。V0.1 阶段不需要写很多测试，够用就好。
